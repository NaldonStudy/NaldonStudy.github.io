# 작업 마무리 및 에러 검증 규칙

## 검증 및 마무리 절차
* **모든 Directive 작업 완료 전 필수 수행**: `.gemini/skills/quality-guard/scripts/validate.cjs` 스크립트를 실행하여 프로젝트의 무결성을 검증하십시오.
* **검증 항목**:
  1. 타입 체크 (`tsc --noEmit`)
  2. 린트 체크 (`eslint`)
  3. 빌드 체크 (`next build`)
* **결과 보고**: 검증 결과를 사용자에게 명확히 보고하고, 모든 항목이 통과된 경우에만 작업을 종료하십시오.

## 커밋 전 사용자 승인 필수
* 어떠한 경우에도 사용자의 명시적인 승인 없이 `git commit`을 독단적으로 수행하지 마십시오.
* 커밋 전에는 항상 스테이징된 파일 목록과 제안할 커밋 메시지를 채팅을 통해 보고하고, 사용자가 "응", "커밋해" 등 승인 의사를 표시했을 때만 실행하십시오.

## ESLint 설정
* ESLint 10+ 버전과 Next.js 16의 호환성을 위해 `eslint.config.mjs` (Flat Config)를 사용합니다. 필요 시 프로젝트에 맞게 규칙을 커스터마이징 하십시오.
